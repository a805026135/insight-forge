# 选做7 · 部署与压测

> 进阶选做章节。跳过不影响主线理解。前置：读过 Phase 10/11。

## 📖 是什么

Phase 10/11 的**运维纵深**——把项目从"能跑"推向"能扛量、能持续交付"：

- **`docker-compose.yml`**：起 MySQL 8 / Redis 7 / Kafka（含延时/DLQ 主题）。
- **Docker 编排**（`deploy/`）：Seckill / Agent / Rule-Engine Worker **资源隔离**部署（热路径与离线 Agent 不抢资源）。
- **JMeter 百万抢购压测**（`deploy/jmeter/seckill-load-test.jmx`）：含无超卖对账 SQL 注释（`MIN(stock)≥0` + 初始−已售=剩余）。
- **GitHub Actions CI 评估闸门**（`.github/workflows/eval.yml`）：CI 跑 eval 阈值，失败阻断发布。

## 🧠 为什么是选做

部署/压测是**运维向**能力，非面试核心编码考察点。有则加分（尤其"压测验证无超卖""CI 评估闸门"是工程素养故事），但跳过不影响讲清后端卖点。运维/性能向面试时读它。

## 关键文件

```
docker-compose.yml                       MySQL/Redis/Kafka 一键起
deploy/Dockerfile*                       Seckill/Agent/Rule-Engine 镜像
deploy/jmeter/seckill-load-test.jmx      百万抢购压测计划
.github/workflows/eval.yml               CI 评估闸门
```

## 如何跑

```bash
# 1. 起中间件（需本机装 Docker）
docker-compose up -d

# 2. 用 integration profile 跑全链路
java -jar insightforge-api/target/insightforge-api.jar --spring.profiles.active=integration

# 3. JMeter 压测（需本机装 JMeter）
jmeter -n -t deploy/jmeter/seckill-load-test.jmx -l result.jtl
```

## ⚠️ 诚实边界

- **沙箱无 Docker / 无 JMeter / 无 CI runner**——以上均**写就、未实跑**，文档已显式标注。
- 本机/容器迁移后才能真跑；沙箱以 `local` profile 零依赖验证 `pong` + 健康页。
- 集成环境的真实端到端联调（建活动→arm→live→抢购→规则引擎消费 tick→调拨→大屏）属 REVIEW §2 待办（Phase 13），未虚报已跑通。

## 与主线的关系

主线 Phase 10/11 只提"有部署编排 + 压测计划 + CI 闸门"。本选做展开运维落地。**部署形态不改变秒杀与规则引擎的代码契约**——它是"怎么交付/怎么验证扛量"的深度，热路径零 LLM 不动。
