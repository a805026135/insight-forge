# 选做4 · 在线校验与分段库存

> 进阶选做章节。跳过不影响主线理解。前置：读过 Phase 9 主线。

## 📖 是什么

Phase 9 里两个「规则上线前如何不翻车」的校验引擎 + 一个库存再分配模型：

- **`ShadowEngine`（影子模式）**：候选规则 vs 当前规则，**只比对不写**——上线前先看新规则会不会乱来。
- **`BacktestHarness`（历史回测）**：重放历史 `sales.tick`，断言 `oversell=0` + SLA 达标。
- **`StockSegmentService`（分段库存模型）**：把一个 SKU 的库存切成 `seg_1/seg_2…`，调拨只追加新段 + `pending` 两阶段预留（先占后确认，失败只删 pending，绝不超卖）。

## 🧠 为什么是选做

- **影子模式**值得讲一句（"上线前先影子校验"是面试好故事），所以主线会提；但 **BacktestHarness + 分段库存**是增强，学习成本不低。
- 特别提一句**分段库存**：它的真实数学只用 `total` 和 `pending` 两个计数器，`segments` 这个 `List<Integer>` 只用于 `segmentCount()` 和 `releasePending` 删最后一段——**等价于一个计数器，却套了"库存切段"的心智模型**。理解它要花力气，但行为上 `调拨 = INCRBY stock by amount` 就够了。

## 关键文件（`insightforge-rule-engine/`）

```
ShadowEngine.java             影子模式（候选 vs 当前，只比对不写）
BacktestHarness.java          历史回放（oversell=0 / SLA）
StockSegmentService.java      分段库存接口（AllocResult record）
InMemoryStockSegmentService.java   默认内存实现（@Profile("!integration")）
RedisStockSegmentService.java      集成实现（INCRBY 写回同一 stock 键）
ControlInstructionExecutor.java    执行调拨/调价（走锁）
ShadowEngineTest / BacktestHarnessTest / StockSegmentServiceTest
```

## 核心入口

```java
shadowEngine.compare(candidatePolicy, currentPolicy);   // 影子比对
backtestHarness.replay(activityId, tickSeries);         // 历史回放
AllocResult r = stockSegment.allocateNewSegment(aid, skid, amount);  // 调拨建新段
stockSegment.confirmPending(aid, skid, amount);         // 确认（库存对用户可用）
```

## 如何跑

```bash
mvn -pl insightforge-rule-engine test
# 含 ShadowTest(2) / BacktestTest(1) / StockSegmentTest(4)
```

## 想简化分段库存？

若觉得"分段"心智负担太重，可塌缩为单一再分配服务，**不改契约**：

```
状态只留 (stock, pending)；reallocate(aid,skid,amount) 直接 INCRBY stock + 记 pending；
删掉 AllocResult / segmentCount / segments 列表。
ControlInstructionExecutor 的调用方式与锁契约完全不变。
```

## ⚠️ 诚实边界

- 分段 / pending / 预测性调拨（滑动窗口线性回归算 TTL<5min 预调拨）目前是**内存原型 + 键名常量**；生产接真实 Redis 分段与时序数据未做。
- `BacktestHarness` 多构造器曾需显式 `@Autowired`（已修复，见 Phase 9 排错表）。
- 集成环境由 `RedisStockSegmentService`（`@Profile("integration")`）替换内存实现，`confirmPending` 用 `INCRBY` 写回**同一** `stock:a:{aid}:s:{skid}` 键。

## 与主线的关系

主线 Phase 9 讲"Drools 执行 DSL → 输出指令 → 写回库存"。本选做补"指令执行前如何校验、库存怎么再分配才不超卖"。**控制面执行契约（锁键 `lock:a:{aid}:s:{skid}` + 原子写回）不变**——影子/回测/分段是"执行得稳不稳"的深度，不改变数据面与热路径。
