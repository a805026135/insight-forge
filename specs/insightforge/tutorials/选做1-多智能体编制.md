# 选做1 · 多智能体编制

> 进阶选做章节。跳过不影响主线理解。前置：读过 Phase 7（Agent 控制面入门）、Phase 8（DSL 产出）。

## 📖 是什么

Phase 8 的**多智能体离线规划**：不只一个 Planner，而是按角色分工的一组 Agent 协作产出护栏 DSL。

- `MultiAgentOrchestrator`（183 行，核心）编排：把"为大促生成护栏策略"拆成子任务 → 分派给角色 Agent → 汇总。
- 角色 Agent（`RoleAgent` 接口 / `LocalRoleAgent` 桩）：选品 / 定价 / 预热 / 风控，各产出一个 `Action`。
- `GuardrailPolicyAgent` 把各角色的动作汇编成一份 `GuardrailPolicy`（护栏 DSL）。
- `IndependentCritic`：独立校验器，确定性程序 → 规则 → 模型/人工三道关。
- `GoldenEvalHarness`：10 条 golden 正向用例防回归。

## 🧠 为什么是选做

主线讲「LLM 离线生成护栏 DSL」**一个 Planner 调一次模型就够**。多角色编制是「框架炫技」：学习成本高（要懂编排、角色分工、子任务、评审官），对讲清"差异化卖点"的边际增益有限——除非你的面试定位就是**「我手搓过多智能体系统」**，否则主线 Phase 8 的单 Planner 故事更省力、效果一样。

## 关键文件（`insightforge-agent-core/.../planning/`）

```
MultiAgentOrchestrator.java   183  编排器（核心）
RoleAgent.java / LocalRoleAgent.java   角色接口 + 确定性桩
GuardrailPolicyAgent.java    58   汇编 DSL
IndependentCritic.java       39   独立校验器
GoldenEvalHarness.java       76   golden 回归
SubTask / Action / PlanningContext / PlanningResult   子任务/动作/上下文/结果
```

## 核心入口

```java
PlanningResult result = orchestrator.plan(new PlanningContext(activityId, goal, constraints));
// result.policy() 即可上线 DSL
```

## 如何跑

- 默认 `LocalDeterministicModelClient` 桩（沙箱无 API Key/外网，确定性产出，可复现）。
- 生产换 `DeepSeekModelClient`（需 `DEEPSEEK_API_KEY` + 外网）。
- 测试：`MultiAgentOrchestratorTest` / `MultiAgentOrchestratorRejectTest` / `GoldenEvalHarnessTest`。

## ⚠️ 诚实边界

- 角色 Agent 是**本地确定性桩**，非真 LLM；生产换 `DeepSeekModelClient` 实现即可。
- `IndependentCritic` 第三道（模型/人工）为桩，默认 `require-human-review=false`。
- `GoldenEvalHarness` 用 seed 用例集（`src/main/resources/golden/phase8-cases.json`）。
- 沙箱未跑真 DeepSeek。

## 与主线的关系

主线 Phase 8 只用**单 Planner** 产出 DSL；本选做展示"多角色分工 + 评审官"的更强编排。两者共用 `GuardrailPolicy` / `GuardrailRule` / `DslCompiler`，**DS L 校验（Fail-Close）逻辑完全一致**——选做只是把"谁来产 DSL"做得更重，不改变数据面契约。
