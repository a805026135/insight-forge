# 选做6 · 实时大屏与可解释性

> 进阶选做章节。跳过不影响主线理解。前置：读过 Phase 10。

## 📖 是什么

Phase 10 的**展示层加分项**：

- **WebSocket 实时大屏**（`DashboardWebSocketHandler`）：商户后台 + 大屏，WS 推送销量/库存/护栏实时变化。
- **策略可解释性**（`ExplainabilityService`）：后端**模板**生成护栏策略的自然语言说明（**非 LLM**），让商户看懂"这条规则为什么这么设"。
- **Prometheus + Grafana**：业务 Gauge（`insightforge_*`）注册进 `MeterRegistry`；Grafana 面板配置。
- **前端**（`insightforge-frontend/`）：React + TS + Vite + Antd + ECharts，建活动/看策略/实时大屏。

## 🧠 为什么是选做

面试核心是**后端卖点**（高并发 + 控制面/数据面分离）。大屏/可解释性是 **demo 辅助**和**AI 治理加分**，不是核心编码能力考察点。做 demo 演示向面试时读它；纯后端向面试，主线 Phase 10 那句"有可观测 + 可解释"就够。

## 关键文件

```
insightforge-api/
  ws/DashboardWebSocketHandler.java        WS 推送
  explain/ExplainabilityService.java       模板可解释（非 LLM）
  config/MetricsConfig.java                Prometheus Gauge 注册
insightforge-frontend/                     React 大屏 + 商户后台
deploy/                                    Grafana 面板配置
```

## 如何跑

- 后端：`ExplainabilityServiceTest`(5) / `DashboardControllerTest`(4) / `ActuatorPrometheusTest`(1) 已实跑通过；`curl /api/dashboard/*` 与 `/explain` 真实返回。
- 前端：`cd insightforge-frontend && npm install && npm run dev`（Vite）。

## ⚠️ 诚实边界

- **沙箱未浏览器验证大屏**（无图形环境）；前端代码写就、未跑视觉回归。
- **Grafana 面板配置写就、未容器验证**（沙箱无 Docker）。
- `ExplainabilityService` 是模板拼接、非 LLM——别对外称"AI 生成解释"。

## 与主线的关系

主线 Phase 10 只提"有可观测 + 可解释"。本选做展开展示层实现。**后端契约（REST/WS/指标）不变**——大屏是"看着爽"的深度，不影响秒杀与规则引擎行为。
